# 四个参考项目的经验汇总

本 Skill 重新编写全部中文说明和模板，只吸收工作流原则。

## agent-self-learning

只沉淀经过验证、非显而易见、可复用且会改变未来行动的经验。证据不足但可能复用的内容先放“待验证”；普通流水账不入库。仓库没有 LICENSE 文件，因此没有复制其源码或文字。

## Skiller

在创建新知识前先查已有技能和经验。每条规则写清触发条件、错误路径、根因、行动和验证。保留失败尝试的原因，并维护待验证、已验证、已替代和已废弃状态。复盘不会自动升级成 Skill。

## mcp-obsidian-vault

区分对话复盘与原子经验：前者还原任务背景，后者用于召回。规则带结构化元数据、来源会话、状态和关联关系。写入必须限制路径并能审计。

## Obsidian Local REST API

搜索与写入分开；写前检查路径越界和文件冲突；更新前备份；使用原子替换；失败后回滚。第一版直接读写本地 Markdown，不安装常驻服务。

## 合并后的判断原则

写前比较必须读候选全文。相同任务可能犯不同错误，因此标题和文本相似度只负责找候选：

- 同任务、同错误、同根因：合并证据。
- 同任务、不同错误：分别保留并关联。
- 不同任务、同根因：保留场景规则，建立关联。
- 新旧证据冲突：保留双方，等待进一步验证。
- 已有规则被更强证据替代：在计划中显式标出，经确认后更新生命周期。
